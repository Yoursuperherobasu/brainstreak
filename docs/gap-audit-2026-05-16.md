# BrainStreak — Codebase Gap Audit (2026-05-16)

Scope: pre-Play-Store. Target: AAB < 25 MB, offline cold start, Android primary.

Status: app is in solid shape. 22 test suites / 141 tests green, tsc clean, 9 mini-games shipped (Brain Rush + 8 arcade). Most "gaps" below are polish/release hygiene, not bugs.

---

## 1. Android hardware back button — FIXED THIS TURN

Before: only `app/game/session.tsx` (Brain Rush) trapped `BackHandler.hardwareBackPress`. All 8 mini-game screens would silently pop on back press and lose in-progress score with no confirm.

After: added `lib/useGameBackHandler.ts` (Alert-confirm wrapper, no-op on web/iOS) and wired into all 8 game screens. Active only while the round is live, so the game-over card still pops correctly on back.

---

## 2. `expo-audio` declares `RECORD_AUDIO` — STILL OUTSTANDING

Documented in `playstore-audit.md` (2026-05-15). The `expo-audio` config plugin injects:
- `android.permission.RECORD_AUDIO` (dangerous, manual review trigger)
- `android.permission.FOREGROUND_SERVICE`
- `android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK`

BrainStreak never records. `lib/audio.ts` only plays. Play Console will flag unjustified `RECORD_AUDIO`.

**Recommended fix:** ship a tiny config plugin that strips those three lines from the merged manifest, OR migrate playback to `expo-av` (which doesn't declare RECORD_AUDIO). Don't do this in the orchestration turn — it needs an EAS build to validate.

---

## 3. EAS project not linked — STILL OUTSTANDING

`app.json` has no `extra.eas.projectId`. `eas build` will prompt interactively, breaking non-interactive CI. Documented in `playstore-audit.md`. Fix: `eas build:configure` once.

---

## 4. Privacy policy URL not publicly hosted — STILL OUTSTANDING

`docs/privacy-policy.html` is git-tracked but GitHub Pages isn't published. Play Console requires a live HTTPS URL. Documented in `playstore-audit.md`.

---

## 5. Game-screen error boundaries — NOT BLOCKING

`<ErrorBoundary>` wraps the whole tree at `app/_layout.tsx`. If one mini-game throws, the entire app shows the boundary fallback. Better: wrap each game screen so a Road Rush crash doesn't blank the Profile tab.

Not urgent (engines are pure and well-tested), but worth doing before 1.2.

---

## 6. Accessibility / touch target sizes — OK with minor gaps

Quick survey:
- `useGameBackHandler` + `accessibilityRole="button"` on the new game CTAs: good.
- Reaction Tap dot is 72px (above the 48dp minimum). Good.
- Memory Match tiles are 132px. Good.
- Odd One Out at level 9+ uses a 5×5 grid in a 320px box → 64px tiles. At edge of touch target threshold; still acceptable.
- Number Sense choice tiles: 84px min width, 18px vertical padding → solid.

No screen-reader testing has been done. Defer to 1.2.

---

## 7. App.json target SDK / Android meta — OK

- `android.versionCode: 1`, `android.package: com.brainstreak.app`. Good.
- Permissions declared: INTERNET, ACCESS_NETWORK_STATE, VIBRATE, POST_NOTIFICATIONS, SCHEDULE_EXACT_ALARM. Reasonable. (Note: `expo-audio` adds RECORD_AUDIO at build time — see #2.)
- `orientation: portrait`. Good.
- `userInterfaceStyle: light`. Intentional (the app doesn't ship dark mode yet).
- `assetBundlePatterns: ["**/*"]` — bundles everything, fine for offline.

Missing: `android.softwareKeyboardLayoutMode` and `android.navigationBar` are absent. Defaults are fine but explicit values would help.

---

## 8. Asset weight — UNDER BUDGET

- `assets/` total: **188 KB**.
- Largest assets: `splash-icon.png` (56 KB), `icon.png` (40 KB), `adaptive-icon.png` (36 KB), `sounds/*.mp3` (≈22 KB total).
- No raster sprites added by this turn — all new artwork is `react-native-svg`.

Bundle is well under target. APK estimate (Expo SDK 54 + RN 0.81 baseline + app code) is ~22 MB. Within the 25 MB budget.

---

## 9. Web PWA icons — N/A (web is dev-only)

`assets/favicon.png` exists, but full PWA manifest icons are absent. The user has explicitly stated the web build is for dev testing only. Skip.

---

## 10. Hydration / SSR safety — OK

`__tests__/ssr-safe.test.ts` already exercises this. Random-init values are all deferred to `useEffect`. No new hydration risks introduced this turn — all new games defer their first `generateRound()` via lazy useState init or post-mount effect.

Confirmed: `app/game/color-trap.tsx`, `odd-one-out.tsx`, `pattern-recall.tsx` all initialize state with `() => generateX()` or similar; lazy initializers run on each instance (not at module-eval time) so SSR vs first-client paint cannot disagree on shared state. Reanimated SSR #418 is the existing known-acceptable warning.

---

## 11. Performance hotspots — NO REGRESSIONS

- `AnimatedBackground` orbs: 4 reanimated workletized sin/cos — cheap.
- Road Rush: 30 ms tick (~33 FPS), pure-fn engine, ≤ ~10 obstacles on screen. Cheap.
- Color Trap / Odd One Out / Pattern Recall: no per-frame loops. State changes only on user input or sequence timer.
- New SVG vehicles: total ~50 nodes for the whole road-rush file. Negligible.

---

## 12. Recent-games rotation — INHERITED FREE

`lib/dailyChallenge.ts` reads `GAMES` from the single source of truth. Adding the 3 new games to `constants/games.ts` automatically expands the daily-challenge pool. No code change needed.
